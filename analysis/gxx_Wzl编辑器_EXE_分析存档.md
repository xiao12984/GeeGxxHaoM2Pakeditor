# gxx Wzl编辑器.exe 分析存档

> 存档日期：2026-08-13
>
> 本文用于保存此前对 `gxx Wzl编辑器.exe` 及相关资源样本的分析结论，避免把已验证事实、项目重建实现和其他 EXE 的界面声明混在一起。

## 1. 结论摘要

### 1.1 gxx Wzl编辑器.exe 本体

目前资料**直接确认的主归档格式只有 1 种：GEEPAK3（`.pak`）**。

已确认内容包括：

- `补丁.pak` 使用 GEEPAK3 签名。
- GEEPAK3 的固定头、索引公式、图片块头和像素载荷结构已经恢复到可审阅实现。
- 已知默认密码 `QQ1167746` 的密钥可用于读取和写回样本结构。

以下内容目前不能据此断言为 gxx 本体已支持：

- WZL/WZX；
- xiami M2Zip；
- GEEPAK2；
- GAMEOFMIR / GAMEOFMIR2；
- JPK；
- 其他 PAK 引擎变体。

原因是仓库中针对 gxx 的直接格式恢复记录只覆盖 GEEPAK3 样本，没有对 gxx 进行逐格式运行验证，也没有恢复其完整原始源码。

### 1.2 不要与当前 C# 重建工具混淆

当前仓库的 C# 工具后来增加了传统 WZL/WZX 和 xiami M2Zip 的读取链路。这些是**项目重建/扩展能力**，不能反推为原始 `gxx Wzl编辑器.exe` 已被确认支持。

因此应区分：

| 对象 | 当前可确认的格式范围 |
|---|---|
| 原始 `gxx Wzl编辑器.exe` | 直接恢复确认 1 种：GEEPAK3 `.pak` |
| 当前 C# 重建工具 | 2 类归档：GEEPAK3 `.pak`、WZL/WZX；M2Zip 属于 WZL 只读变体 |

## 2. 目标样本与证据

### 2.1 gxx 样本

`analysis/FORMAT.md` 记录的样本为：

- `gxx Wzl编辑器.exe`
- `补丁.pak`
- `补丁.pak` 的 SHA-256：`E90A06BC7FF33C745FA5D97D541B404382F814EC0907FFD020C2668D9D0431D6`
- 记录中的 gxx EXE SHA-256：`8827EDA8BEC75A4C01B8802AFCE39DAAC8D44D1EA7AE57635184755A1DCB6E83`

### 2.2 直接格式证据

样本文件头为：

```text
07 47 45 45 50 41 4B 33
```

ASCII 部分为 `GEEPAK3`。这证明样本属于 GEEPAK3，而不是仅凭 `.pak` 扩展名猜测格式。

### 2.3 证据等级

| 等级 | 含义 |
|---|---|
| A：直接确认 | 文件头、样本结构或现有代码可以直接验证 |
| B：高置信推断 | 多项旁证一致，但缺少完整动态验证 |
| C：未确认 | 只有字符串、界面、旁路文件或推测，不能作为格式实现依据 |

本档案对 gxx 本体的“1 种”结论属于 A 级范围；对其他格式不作超出证据的扩展。

## 3. GEEPAK3 格式恢复记录

### 3.1 文件布局

```text
0x000  8 字节 GEEPAK3 签名
0x008  2 字节保留字段
0x00A  256 字节加密全局头
0x10A  UInt32 索引表
后续   图片块头和像素载荷
```

固定头总长度为 `266` 字节：`8 + 2 + 256`。

### 3.2 已确认的全局头字段

解密后的 256 字节全局头中，已确认字段如下：

| 偏移 | 类型 | 含义 | 已知值 |
|---:|---|---|---:|
| `0x2A` | UInt32 | HeaderSize | `266` |
| `0x2E` | UInt32 | SlotCount | 槽位数量 |
| `0x32` | UInt32 | Version | `2` |
| `0x36` | UInt32 | IndexOffset | `266` |

标题字段已确认出现 `www.gameofmir.com` 或 `www.gameofmir2.com`。

### 3.3 索引解密公式

对第 `i` 个索引项：

```text
offset[i] = encrypted[i] XOR NOT(indexKey[i % 64]) XOR i
```

索引密钥表长度为 256 字节，公式按 64 个 UInt32 密钥循环使用。

### 3.4 图片块头

图片块头固定为 16 字节：

```text
+0x00 Byte   图片类型
+0x03 Byte   Alpha / 标志字段
+0x04 UInt16 宽度
+0x06 UInt16 高度
+0x08 Int16  X 偏移
+0x0A Int16  Y 偏移
+0x0C UInt32 zlib 长度，0 表示原始载荷
+0x10        像素载荷
```

在 GEEPAK3 中，图片块头和全局头都需要使用对应密钥解密。

### 3.5 已确认像素布局

当前格式记录确认了 6 种图片像素布局：

1. 8 位固定调色板（Palette8）
2. 16 位 R5G6B5
3. 24 位 RGB
4. 24 位 RGB 加独立 8 位 Alpha 平面
5. 32 位 X8R8G8B8
6. 32 位 A8R8G8B8

载荷可能是 zlib 压缩数据，也可能是未压缩的原始像素数据。

## 4. 密码与密钥链路

### 4.1 已知密钥角色

GEEPAK3 使用三组密钥：

| 密钥 | 长度 | 用途 |
|---|---:|---|
| `indexKey` | 256 字节 | 解密索引偏移 |
| `globalHeaderKey` | 256 字节 | 解密全局头 |
| `imageHeaderKey` | 1024 字节 | 解密图片块头 |

### 4.2 默认密码

仓库记录了原编辑器常见的默认密码：

```text
QQ1167746
```

该密码对应的公开密钥数据可用于 GEEPAK3 样本的读取与写回。

### 4.3 未恢复的部分

原程序将任意密码交给受保护的派生过程。当前没有恢复为可审计 C# 算法的内容包括：

- 任意密码到三组密钥的完整派生算法；
- 是否绑定机器、许可证或运行环境；
- 密码失败时的完整分支；
- 原 EXE 的具体保存、转换和改密策略。

因此不能仅凭密码表或字符串推断出完整的原始密码算法。

## 5. 与其他分析样本的边界

### 5.1 当前 C# 重建项目

仓库 README 明确说明：项目是“参考 `gxx Wzl编辑器.exe` 的文件访问行为和 GEEPAK3 样本格式重建”的 C# 工具，不是原 Delphi 工程的逐行反编译。

后续提交增加了：

- 项目自建 WZL/WZX 的打开、编辑和写回；
- xiami M2Zip WZL/WZX 的只读读取；
- 新建 PAK 与 WZL/WZX 资源。

这些功能属于当前项目实现边界，不属于 gxx 本体的直接证据。

### 5.2 GM工具箱 V3.10.0.exe

`analysis/GM工具箱_V3.10.0_文件与密码管理链路.md` 分析的是另一个目标：`GM工具箱-资源编辑器_V3.10.0.exe`，产品标识为 `MIRViewer`。它不能与 `gxx Wzl编辑器.exe` 合并统计。

该另一个 EXE 的欢迎页 UI 宣称支持以下 10 个外层格式家族：

- PAK
- WIL
- WZL
- MIZ
- LIB
- WTL
- ZL
- PDB
- JPK
- ROM

窗口标题另外列出 `WIS`、`PSK`，若把标题中的两项也算入 UI 宣称范围，则为 12 类。其 PAK 行还列出多个引擎变体：GOM、GEE、LEG、V8、龙族、翎风、KSF、361、Apple、GOM 二次加密。

该清单是**界面声明**，文档明确指出不能证明每一种格式都已经完成二进制读写验证。因此这些数量不能回答“gxx Wzl编辑器.exe 支持几种”。

## 6. 当前不应下的结论

以下说法目前都缺少对 gxx 本体的直接证据：

- “gxx 支持 WZL/WZX”；
- “gxx 支持 M2Zip”；
- “gxx 支持 10 种 PAK 引擎”；
- “gxx 支持 JPK 996/XUW”；
- “gxx 支持 GEEPAK2、GAMEOFMIR 或 GAMEOFMIR2”；
- “另一个 GM工具箱的 UI 清单就是 gxx 的实际格式矩阵”。

正确表述应是：**此前对 gxx 样本已直接确认的格式为 GEEPAK3，按主归档格式计 1 种；其他格式仍需原 EXE 的动态行为、授权样本和独立格式样本继续验证。**

## 7. 后续验证建议

如需继续研究原 EXE，建议在获得授权样本和隔离环境后进行：

1. 记录打开不同扩展名时的文件访问路径和错误分支。
2. 使用已知密码、错误密码、无密码输出分别观察行为。
3. 对转换、合并、批量改密前后的文件头和索引做样本差分。
4. 对 `.pak`、`.jpk`、`.wzl/.wzx` 分别建立独立样本，不把扩展名直接等同于内部格式。
5. 保留原文件哈希、操作日志和输出副本，避免覆盖授权样本。

## 8. 分析限制与安全边界

- 本次记录以已有静态分析、格式恢复记录和仓库代码为依据。
- 未对目标 `gxx Wzl编辑器.exe` 做动态调试、解包、打补丁或写回测试。
- 保护层、虚拟化和高熵代码会使原始字符串和静态命中不可靠。
- 本文不把当前 C# 重建代码冒充为原始 Delphi 源码。
- 本文不把另一个 `GM工具箱 V3.10.0.exe` 的 UI 声明冒充为 gxx 的实际能力。
